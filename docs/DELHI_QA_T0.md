## 1. Proof that the running game can be driven and measured from here
Done in the built-in browser pane on this Mac, server `python3 tools/serve.py 8791`, address `/?play&at=delhi&dev&q=low`.

| Check | Result |
|---|---|
| Delhi loads, WebGL canvas (`#view`, 1024 x 768) renders | yes, screenshot taken: Outer Circle at CP, car, signals, shopfronts |
| Telemetry read | `window.__where()` gives lat, lon, x, z, heading, street and class, area, nearest landmark; `window.__signs` gives sign counters; `window.__cityNav` exposes `router`, `G`, `route`, `steps` |
| Route planning on the real graph | `__cityNav.router.plan(x0,z0,yaw,x1,z1)` from the start to India Gate (x 2000, z 108): 4,023 m, 94 nodes, 64 ms, 6+ turn steps (Outer Circle, Kasturba Gandhi Marg, Rotary No 5, Jaswant Singh Road, Man Singh Road ...) |
| Input through the real pipeline | a dispatched `keydown` W held 3 s then `keyup` moved the car 29 m through the normal physics. A single `computer.key` press is too short (the car does not move); hold by event dispatch |
| Frame time (visible tab, `q=low`, DPR 1, 1052 x 664, 180 frames, desktop) | p50 5.7 ms, p95 7.6 ms, max 11 ms. This is a development Mac, not a phone and not a quality tier a player uses; do not quote it as device performance |

Not proved: a headless or CI run (the pane is a visible window), real iPhone or Android (Stream B's iPhone 14 Pro run, A-2026-11-22-13, is the only phone number: 43.5 fps average on medium), a screenshot written to a file by script (the pane returns images to the session only).

## 4. Proposed smallest safe T1 (needs the owner's go)
- One new file `src/debug/delhi_test_adapter.js`, loaded only when the address has `dev` and `testdrive=1`; when absent the game is unchanged. A guard in the file itself refuses to install without both flags.
- It wraps existing objects only: `where()` for position, `__cityNav.router` for routes, the existing keyboard handler (event dispatch) for controls, `__cam` for cameras, a `requestAnimationFrame` timer for frame times. No second physics, no second router.
- Calls: `ready()`, `setSpawn`, `setCamera`, `setControls(ticks)`, `followRoute(waypoints)`, `getTelemetry()`, `capture(name)` (metadata JSON; the image is taken by the pane tool), `reset()`.
- The one shared-file touch: one line in `src/main.js` (a dynamic `import()` guarded by the two flags). Reserve it with Stream B before editing (CLAUDE.md rule) and make it its own small commit.
- Runner and fixtures (`tools/run_delhi_test.mjs`, `tools/delhi_test_routes.json`) come in T2; nothing there before the adapter is approved. A WebGL-less machine reports `NOT RUN - ENVIRONMENT UNSUPPORTED`, never PASS.
- First scenario: the CP to India Gate route above, driven by `followRoute`, with a telemetry sample every second and a screenshot at start and end. Then Todarmal (x 2190 to 2470, z about -1640) and one real flyover chosen from the pack by `tools/audit_city.mjs` output, not by me.
